# Боты APPGRADE

Два отдельных бота используют одну базу PostgreSQL. Сайт читает цены из базы и сохраняет заказы. Бот прайса принимает Excel; бот заказов доставляет сохранённые заявки в заданный личный чат или группу. Номер заказа сохраняется при повторной отправке после сетевой ошибки.

## Подключение Telegram

1. В [@BotFather](https://t.me/BotFather) выполните `/newbot` два раза: для прайса и для заказов. Сохраните два разных токена в переменных окружения, не в исходном коде.
2. Скопируйте `.env.example` в `.env.local` для локального запуска. Заполните `DATABASE_URL`, `TELEGRAM_PRICE_BOT_TOKEN` и `TELEGRAM_ORDERS_BOT_TOKEN`.
3. В `TELEGRAM_PRICE_ADMIN_IDS` укажите числовые Telegram ID сотрудников через запятую. Доступ закрыт по умолчанию. Бот принимает прайсы только в личном чате от этих пользователей. ID можно узнать через доверенный инструмент Telegram; работающий бот также сообщает отправителю его ID в ответ на `/start`.
4. Для заказов откройте второго бота и нажмите «Начать», либо добавьте его в рабочую группу и отправьте `/id@имя_бота`. Он ответит ID чата. Укажите этот ID в `TELEGRAM_ORDERS_CHAT_ID` у сайта. Для групп ID обычно отрицательный. Боту нужно право отправлять сообщения.
5. Укажите публичный адрес сайта в `APP_ORIGIN` и `NEXT_PUBLIC_SITE_URL` (например `https://shop.example.ru`, без завершающего `/`).

Боты используют long polling: входящий публичный URL для них не нужен. Если токен ранее использовался с webhook, сначала удалите тот webhook. Один токен нельзя одновременно использовать в двух запущенных процессах. [Telegram Bot API](https://core.telegram.org/bots/api#getupdates).

## Локальный запуск

Нужен Node.js 22.13+ и PostgreSQL. Рекомендуется Node.js 24. Файл `.env.local` автоматически читается скриптами; Next.js также читает его.

```sh
npm ci
npm run db:migrate
npm run dev
```

В двух дополнительных терминалах:

```sh
npm run bot:prices
npm run bot:orders
```

Без настроенной базы сайт показывает исходные цены; оформление заказа возвращает сообщение о ненастроенном приёме. Если база настроена, но недоступна, запись заказа не считается успешной. Отключение бота заказов не удаляет заявки: они останутся в очереди до его запуска.

## VPS через Docker Compose

1. Установите Docker с Compose. Скопируйте `.env.example` в `.env`, заполните токены, ID и адрес сайта. Задайте длинный случайный пароль `POSTGRES_PASSWORD` из латинских букв и цифр. В Compose строка соединения с базой формируется автоматически; `DATABASE_URL` из файла используется только при запуске вне Docker.
2. Выполните `docker compose up -d --build`. Миграция выполнится перед запуском сайта и ботов. Токены не попадают в Docker image; база не публикует порт наружу.
3. Настройте HTTPS через Caddy/Nginx с проксированием на `127.0.0.1:3000`. Для публичного магазина также ограничьте частоту запросов к `/api/orders` на reverse proxy.
4. Проверьте процессы: `docker compose ps`; журналы: `docker compose logs --tail=100 price-bot order-bot web`.
5. Отправьте боту заказов `/id`, внесите ID в `.env` и примените его командой `docker compose up -d web`.

При обновлении исходников снова выполните `docker compose up -d --build`. Именованные volumes хранят PostgreSQL и исходные прайсы независимо от контейнеров. Не используйте `docker compose down -v`: эта команда удаляет volumes с данными.

## Загрузка и откат цен

Отправьте `.xlsx` до 10 МБ боту прайса. Он вернёт полный текстовый отчёт и кнопку «Применить цены», если есть допустимые изменения. В отчёте указаны старые/новые цены, идентификаторы вариантов и исходные ячейки. Кнопка доступна только загрузившему файл администратору в том же чате. Загрузка действует 24 часа; после другого обновления понадобится загрузить её заново.

После подтверждения цены меняются одной транзакцией. Открытые страницы, корзина и избранное получают обновление в течение минуты или при возвращении в окно. Перед сохранением заказа сервер проверяет актуальную цену. При расхождении покупателю предлагается проверить новую сумму.

Команда `/rollback` показывает подтверждение восстановления предыдущих цен. Откат также сохраняется в истории. Повторное нажатие старой кнопки не откатывает более новую версию.

### Формат Excel

Сохраняйте названия листов и расположение столбцов исходного файла `PRICE KINGSTORE, APPGRADE 14.19.xlsx`. Наименование товара — столбец A.

| Листы | Столбец цены |
|---|---|
| iPhone, macbook, iPad, Apple Watch, AirPods, Samsung S, PlayStation, Dyson, Marshall , JBL | B |
| Google, Xiaomi, Fujifilm | C |

На сайте отображается только сумма в рублях, без уточнения способа оплаты. Закупочная цена и дополнительные цены из Excel не публикуются.

Сопоставление точное после нормализации регистра, пробелов, единиц памяти и известных различий названий (например Samsung Galaxy / Samsung). Строка без цвета обновляет все существующие цвета данной конфигурации, строка с цветом — только его. Разные SIM и память не объединяются. Неизвестные товары не создаются автоматически.

Листы Ray-Ban и Yandex не импортируются и отмечаются в отчёте: соответствующих категорий в каталоге нет. На листе Ray-Ban исходного файла фактически встречаются Samsung; он намеренно не используется как второй источник цен Samsung.

Пустые значения, прочерки и ошибки формул сохраняют старую цену и попадают в предупреждения. Нулевые/отрицательные цены и противоречащие дубликаты блокируют применение файла. Поддерживаются арифметические формулы с числами, ссылками внутри листа, скобками и процентами; они пересчитываются из исходных ячеек. Внешние ссылки и другие функции не исполняются. Цены округляются до целого рубля.

Проверка исходного файла без базы, Telegram и изменения цен:

```sh
npm run prices:check
# или
npm run prices:check -- "путь/к/прайсу.xlsx"
```

## Заказы

Уведомление включает номер заказа, имя, телефон, Telegram (если выбран), город, самовывоз/адрес доставки, товары с конфигурациями и количеством, услуги, итог и комментарий. Суммы и названия рассчитывает сервер. Данные сохраняются в `appgrade_orders`; токены и сведения клиентов не входят в публичный API цен.

При сбое Telegram бот повторяет отправку с увеличивающейся задержкой до часа. Большие заказы разбиваются на сообщения. Уже отправленные части отмечаются в базе. Если процесс остановится между принятием сообщения Telegram и сохранением отметки, уведомление может прийти повторно с тем же номером заказа; сам заказ не дублируется.

Для проверки очереди используйте SQL:

```sql
SELECT id, created_at, attempts, next_attempt_at
FROM appgrade_orders WHERE notified_at IS NULL ORDER BY created_at;
```

## Резервные копии

Ежедневно сохраняйте дамп PostgreSQL и архив volume `uploads` в отдельное хранилище. Настройте резервные копии VPS у провайдера. Пример получения дампа в Linux (файл содержит данные клиентов, доступ только владельцу):

```sh
umask 077
docker compose exec -T db pg_dump -U appgrade -d appgrade -Fc > appgrade-backup.dump
```

Проверьте восстановление дампа в отдельную тестовую базу через `pg_restore`. История цен и исходные файлы нужны для аудита, но не заменяют внешнюю резервную копию базы заказов.

## Проверки разработки

`npm test` проверяет настоящий прайс, формулы, конфигурации, права, PostgreSQL-транзакции во встроенном PGlite, откат, запись заказов, повторные запросы и доставку после сбоя Telegram. Реальные сообщения при тестах не отправляются. `npx tsc --noEmit`, `npm run lint`, `npm run build` проверяют сайт.
