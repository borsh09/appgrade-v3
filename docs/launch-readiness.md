# Готовность APPGRADE к запуску

## Проверка перед открытием продаж

`npm run check:launch` проверяет публичный HTTPS-адрес, переменные окружения без вывода секретов, контакты городов и наличие страницы политики. Для проверки работающего сайта: `npm run check:launch -- --url=https://ваш-домен`.

`/api/health` возвращает 200 только при настроенном приёме заказов и доступной таблице цен. Ответ 503 блокирует отправку из корзины и показывает покупателю контакты магазина. Проверка не подтверждает, что Telegram-бот запущен или что уведомление доставлено: это нужно проверить отдельно.

## Данные, которые ещё нужны

- Домен: сейчас APP_ORIGIN и NEXT_PUBLIC_SITE_URL указывают на localhost. После изменения NEXT_PUBLIC_SITE_URL пересоберите сайт. На локальном адресе индексация закрыта; sitemap появляется для публичного HTTPS-адреса.
- Реквизиты продавца и контакт для обращений о персональных данных. Страница политики пока отсутствует. Текст и условия обработки нельзя заполнить выдуманными сведениями.
- Адрес, телефон и режим работы магазина в Сибае. Сейчас доступна связь с общим Telegram магазина.
- Подтверждение условий оплаты, гарантии, доставки и Trade-In, указанных на сайте, со стороны владельца магазина.

## Рабочий сервер

Инструкция по PostgreSQL, миграциям и двум ботам: [telegram-setup.md](telegram-setup.md). Compose автоматически формирует DATABASE_URL из POSTGRES_PASSWORD; для запуска через `npm start` DATABASE_URL требуется отдельно. Локальный Docker Engine во время проверки не был запущен.

1. Настройте домен, HTTPS и переменные окружения на сервере.
2. Запустите `docker compose up -d --build`, проверьте миграцию и оба бота через `docker compose ps`.
3. Проверьте `/api/health` и `npm run check:launch -- --url=https://ваш-домен`.
4. С согласованными тестовыми данными оформите один заказ и убедитесь, что его номер совпадает с уведомлением менеджеру. Проверка интерфейса сама по себе не подтверждает доставку уведомлений.
5. Настройте резервное копирование PostgreSQL вне сервера и проверьте восстановление на отдельной базе. Не используйте `docker compose down -v` на рабочей базе.

## Что изменено

- Сервер больше не отдаёт пустой сайт до чтения localStorage; контакты доступны в исходном HTML.
- Единые ссылки меню и каталога, корректные 404, отдельные метаданные товаров и служебных страниц.
- Исправлены название MacBook и SIM в популярных товарах; убраны выдуманные остатки и безусловное обещание выдачи сегодня.
- Убраны неподтверждённые цитаты отзывов; сохранены ссылки на площадки.
- Выбор города использует модальное окно с блокировкой фона; мобильное меню удерживает клавиатурный фокус.
- Корзина проверяет доступность приёма, Telegram username и границы количества. Скрытое поле адреса исключено из клавиатурной навигации.
- Добавлены robots, sitemap, заголовки безопасности, тесты ссылок и соответствия популярных карточек реальным SKU.

## Изолированная проверка production-сборки

В PowerShell задайте `$env:APPGRADE_BUILD_DIR='.next-production'`, выполните `npm run build`, затем `npm start -- --port 3001`. Каталог сборки не конфликтует с работающим `next dev`. Для обычного запуска переменную APPGRADE_BUILD_DIR задавать не нужно.
