# Проверка безопасности перед запуском — 3 октября 2026

Проверены исходный код, зависимости, валидация заказов, доступ к приватным API, обработка файлов и HTTP-поведение локальной production-сборки. Проверки не создавали заявки в рабочей базе и не отправляли сообщения Telegram. Для интеграционных тестов использовался PGlite; HTTP-экземпляр работал с отключёнными DATABASE_URL и Telegram и отдельным тестовым паролем.

## Исправления

| Находка | Результат |
| --- | --- |
| Next.js 16.3.4: npm audit сообщил одну критическую уязвимость GHSA-vcvr-r3jv-pc5j в next/og ImageResponse | Next.js обновлён до 16.3.8, версия закреплена в package.json и lock-файле. После обновления audit: 0 известных уязвимостей. Использование next/og/ImageResponse в коде приложения не найдено; выполнение кода атакующим на этом сайте не воспроизводилось. |
| Проверка Excel доверяла объявленному в ZIP распакованному размеру | До ExcelJS/JSZip проверяются локальные заголовки, имена, границы данных и реальный размер распаковки. inflateRawSync использует maxOutputLength; поддельный размер не позволяет выделить неограниченную память. Общий лимит 50 МБ и 1000 записей сохранён. Импорт требует авторизации. |
| assertOrigin пропускал запросы без Origin и игнорировал Referer | Изменяющие запросы требуют разрешённый Origin либо Referer. Отсутствующие, чужие и null-источники блокируются. Совместимость localhost/127.0.0.1 с одинаковым портом сохранена. Это усиление CSRF-защиты; обход подписанной сессии не обнаружен. |
| JSON-обработчики принимали text/plain | readJson принимает application/json и отклоняет простые типы форм с 415. Заказы переведены на общий обработчик. |
| Превышение размера multipart не отменяло входящий поток; общего срока чтения тела не было | Чтение тела ограничено размером и 30 секундами; при превышении лимита или срока поток отменяется. Проверены ответы 413 и 408 на синтетических потоках. |

Существующие интеграционные тесты дополнены Origin и корректным Content-Type, как у запросов браузера. Для тестирования отмены multipart Node FormData сначала сериализуется: это исключает ошибку синтетического производителя потока Node при отмене.

## Что выдержало проверки

- Подделка подписанной cookie и Basic authentication не дают доступа к админке.
- Приватные API чтения заказов, изменения цен и импорта требуют авторизации; CSRF проверяется до операций с базой.
- Подмена цены, количества, услуг, города и оценки Trade-In блокируется серверной валидацией.
- SQL-параметры передаются отдельно; имена таблиц выбираются из разрешённых вариантов. Инъекция в type API списка заявок отклонена.
- Rate limit входа выдерживает подмену клиентских IP при отключённом доверии прокси.
- 18 HTTP-проверок прошли: служебные файлы не выдаются, приватные API возвращают 401, поддельные источники — 403, защитные заголовки присутствуют.
- В проверенном коде приложения не найдены eval/Function или dangerouslySetInnerHTML для вывода пользовательских данных.

## Верификация

60 тестов проекта, TypeScript и lint изменённых файлов прошли. Production-сборка Next.js 16.3.8 проверена. Результаты HTTP-проверок сохранены в .tmp-qa/security-http-results.json; audit до/после — в .tmp-qa/security-audit-before.json и security-audit-after.json.

## Границы проверки

Это аудит кода и локального production-экземпляра, а не гарантия отсутствия любых уязвимостей. Публичный сервер, TLS, настройки прокси, права рабочей базы, резервные копии и нагрузочная устойчивость инфраструктуры не проверялись. Для публичного запуска APP_ORIGIN должен быть точным HTTPS-адресом магазина; TRUST_PROXY=true допустим только за прокси, который перезаписывает X-Real-IP. Изменяющие API намеренно больше не принимают скрипты без Origin/Referer; внешним клиентам потребуется корректный источник и Content-Type.
